# Hackways public SEO audit - 2026-10-26

## Executive summary

Hackways' sampled public pages are reachable over HTTPS, have a single H1 and
descriptive titles, and expose their main content in server HTML. The existing
robots file permits crawling and links to a valid XML sitemap. Login is noindex;
an invented public URL correctly returns 404. There is no observed site-wide
indexing block in this sample.

The clearest improvements are sitemap coverage, explicit canonical URLs on public
program/community pages, and page-specific directory descriptions. These have
been implemented in source. Production has not been restarted or changed for this
audit: applications are live and the applicant journey must remain stable.

The remaining priorities are a consistent www redirect, responsive program-banner
delivery, and a bounded public-entity sitemap. Ranking, traffic, rich-result
eligibility and Core Web Vitals are unmeasured; no numerical health score is
assigned without those inputs.

## Scope and method

- Business: event discovery, community hosting and open program applications.
  SEO goals inferred from existing product copy: help people find events,
  communities, organizer information and the ambassador role.
- Read the project rules, architecture, existing metadata/OG helpers, page

  packages in the user's Codex skills directory. Existing user skills retained.
  No upstream installation scripts, hooks or Python runtime were executed, and no
  application dependency was added. Optional bundled CLI/runtime setup remains

- Anonymous, read-only live HTTP sample: home, robots, sitemap, ambassadors,
  programs, ambassador program details, discover, spaces, about, help, organizers,
  contact, privacy, login and an intentionally missing URL. No production
  applicant records were edited and no emails were sent.
- Checked HTTP, www, legacy app-host and trailing-slash behavior separately.
- No product-marketing context file was found in the working repository.

Google describes sitemaps as a discovery aid, not an indexing guarantee, and
recommends consistent canonical signals across links and sitemaps:
[sitemaps](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview),
[canonical URLs](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls).

## Verification and limits

- Public-web `npm test`: passed type-check and lint, no ESLint warnings/errors.
- Core-web `npm test`: passed type-check and lint, no ESLint warnings/errors.
- Tracked source audit and `git diff --check`: passed.
- Temporary loopback Next.js previews use only anonymous reads from the actual
  approved public APIs; no local mock records or production mutations.
- Generated HTML checks passed for the sitemap's three added directories,
  Programs canonical/description, ambassador program canonical, Discover
  description, Space pagination canonical, search noindex/follow and authenticated
  community-tab redirection to the existing noindex login page. Cold compilation
  initially timed out and one Programs preview returned a local `useContext` 500;
  a subsequent warmed request returned 200 with the expected metadata. No change
  to application or auth behavior was made to suppress this development error.
- Existing preview ports 4000/4001 were not running. No production service was
  started/stopped to run this audit.
- PageSpeed Insights anonymous request returned HTTP 429. No lab score, field
  LCP/INP/CLS, load-capacity assertion or performance ranking is reported.
- No connected Search Console/GA4 data was available to this audit. A search-engine
  `site:hackways.in` query returned no results through the available tool; this is
  not proof that the domain has zero indexed pages.
- Browser/rendered mobile QA and Rich Results Test were not executed. Server HTML
  and source review do not replace rendered schema/accessibility validation.
- No full production build or deployment was performed. These changes require the
  existing off-VM CI and normal scoped release process before appearing live.

## Action sequence

1. Release the verified metadata-only changes through existing CI when appropriate
   for the live application window. Validate sitemap and canonical output before
   treating them as live fixes; no form, auth, backend, mail or database contract
   changes are needed.
2. Verify the www redirect separately, including paths, query strings and existing
   session behavior; retain a rollback for ingress configuration.
3. Reduce thumbnail transfer cost while preserving the supplied banner and OG
   artwork, then measure mobile loading with available PageSpeed/CrUX data.
4. Add a bounded public-entity sitemap and factual schema only after their data
   contracts and publication/privacy filtering are reviewed.
5. Connect Search Console, submit the sitemap and inspect representative URLs.
   Establish impressions, clicks, CTR and chosen canonicals before prioritizing
   content expansion or claiming ranking improvements.
