# Admin console: local review

The admin application runs at `http://localhost:3003/` with dedicated page paths and ordinary document navigation.

| Path | Data and purpose | Go engine |
|---|---|---|
| `/` | Directory of administration pages | No private data fetch |
| `/events` | All non-deleted event publication states | Core |
| `/spaces` | Active and archived spaces and membership totals | Core |
| `/people` | Accounts, email verification and explicit platform access | Global |
| `/registrations` | Registration references, identities, event and state | Core |
| `/tickets` | Ticket references and recorded check-in state | Core |
| `/moderation` | Draft and unpublished event inspection | Core |
| `/messaging` | Email outbox delivery state, retries and scheduling | Global |
| `/storage` | Attached event banner and avatar metadata | Global |
| `/audit` | Recorded event/registration actions, actor and timestamp | Core |
| `/login` | Dedicated platform admin sign-in | Global |

## Navigation and appearance

Pages use full document links without fragments or section scrolling. Search is a GET form; `q`, `page`, and `status` are preserved in clean destination paths. Filters use `@hackways/ui/select`. Each data page fetches its own collection, paginates at 20 rows, cancels unmounted requests and times out after 15 seconds. Network failures show a retry action. Authentication failures leave the entire console for sign-in or Access denied; no per-module sign-in prompt is rendered. No Create button appears in the console.

The viewport is split into independently scrolling navigation and main content. On desktop the sidebar stays beside the content. On small screens navigation occupies a bounded top region and main content retains its own scroll area. This keeps the sidebar from moving when main content scrolls. Scrollbar tracks, thumbs and arrows are hidden throughout the admin app, including tables and shared select menus, while native scrolling remains enabled. Sidebar, workspace and table regions are keyboard focusable for scrolling.

The shell uses the application's Google Sans Flex/FG Futurist fonts, semantic palette, button/input implementations and Hugeicons. The shared UI provider and control styles remain mounted. Font licences and assets are included in the app and future image packaging.

## API and authorization

Core serves `/api/v1/admin/core/{events,spaces,registrations,tickets,moderation,audit}`. Global serves `/api/v1/admin/global/{people,messaging,storage}`. Collections remain read-only; protected detail reads and the reviewed local record actions are described below. Core actions reuse the existing lifecycle workflows rather than duplicating their business rules in Next.js.

All admin reads require a verified account with a live explicit `platform_administrators` record and a separate `platform_admin_sessions` marker for the current PostgreSQL session. Ordinary session cookies and ordinary sessions relabelled as admin cookies are rejected. Grants are checked on every read; revocation blocks existing admin sessions. Responses are private and not cached. Queries are generated by sqlc, parameterized and limited to at most 100 rows under a three-second request context.

Global adds `POST /api/v1/auth/admin/login`, `POST /api/v1/auth/admin/logout` and `GET /api/v1/auth/admin/me`. Login uses the existing account password, persistent identity rate limiter and a transaction to create a dedicated 30-minute admin session. Its cookie is `__Host-hackways_admin_session` with Secure, HttpOnly, Path=/ and SameSite=Strict. Passwords, session tokens, raw email payloads, provider errors and signing material are not returned in inspection APIs. Asset URLs omit query strings and fragments; details link only HTTPS URLs.

Admin document requests are gated in `middleware.ts` before Next.js renders any dashboard or RSC payload. The gate asks the existing Go identity endpoint to verify the session and explicit grant, with a four-second timeout and no cached permissions. Missing/invalid sessions redirect to `/login` with a local return path; authenticated accounts without an admin grant go to `/access-denied` (403). Identity-service failures show the separate `/auth-unavailable` document (503), never the console. A verified administrator with only an ordinary session must still complete dedicated admin sign-in; ordinary sessions never open the console.

The `(console)` route group keeps all existing URLs and independently checks access in its server layout and async shell. React cache deduplicates those two checks only within the render. This additional server guard prevents the shell from being serialized if a request reaches rendering without passing middleware. No incoming header asserts authorization. Login and denial documents have no dashboard navigation. Logout/expiry redirects remove the console; API authorization remains independently enforced by both Go services. See [the shared authentication UI](../design/AUTHENTICATION.md).

Local entry verification covers all ten anonymous dashboard paths, RSC and prefetch requests, spoofed internal headers, a real approved local dedicated session and immediate rejection after logout. Anonymous/rejected responses contain no dashboard shell payload. The separate 403/503 documents were checked. Global auth/admin/platform package tests passed against the disposable CI database, including ordinary/ungranted/relabelled/invalid session cases; no production authorization changes were applied.

## Record details and reviewed actions

Each of the nine data modules now links to `/{resource}/details/{id}`. Storage additionally preserves `kind=event_banner|avatar`; audit IDs are positive integers and other IDs are UUIDs. Server fetches use the same Go admin gate, no cached data, a six-second timeout and validated scalar DTOs. Detail pages show real record fields and cross-links, retain honest empty/error states, and fetch related records in pages of 20 using a 21-row lookahead. People include events, registrations, active sessions, messages and activity; events include registrations, tickets and activity; spaces include events, members and activity. Audit details show recorded metadata without editing controls.

Core actions edit event title/description/capacity/visibility, apply publish/unpublish/cancel transitions, edit/archive/restore spaces, change permitted registration states and manually check in eligible tickets. They reuse the existing locked workflows, registration windows, queue/capacity checks, version conflicts and notification outbox. The privileged context retains the real administrator as audit actor while scoping management to the record's owner.

Global actions edit a person's display name, grant/revoke platform access, revoke a selected account session, retry an eligible failed outbox entry and detach an attached image. Access changes require the user-approved role controls: no self access change, no last-admin removal, verified email before granting and dedicated-session revocation when access is removed. Current-session revocation uses sign-out. Message retry requires failed state with no recorded first provider attempt; it is not arbitrary message replay. Detachment changes event/profile metadata and retains the Azure blob.

Every action requires a recorded reason, allowed admin origin, current version where applicable and idempotency key. Go rechecks authorization, validates the action and commits its audit/receipt with the change. An uncertain request can retry the same key/body/reason; a changed request using that key conflicts. The UI preserves failed input and reports success only after the actual API succeeds. Audit records have no edit/delete route. See [the exact methods, bodies, headers and retry contract](../API.md#reviewed-local-record-actions).

## Local setup and release boundary

Migration `000009_platform_administration` is additive and seeds no privileges or accounts. `000010_admin_detail_indexes` adds reversible audit/entity/actor and recipient-message timeline indexes without changing grants. Migration 000010 has been applied only to the isolated local test databases and restored local preview. Production still requires separately reviewed migrations and an explicit grant to an existing verified account before admin sign-in can work. No production grant or migration was applied in this task. Never use CI fixtures as application demo data.

Development-only Next.js rewrites send the three admin API prefixes to the existing loopback Go services on 8081 and 8082. The local Go environment allows `http://localhost:3003` and its IPv4 loopback equivalent. The admin development server binds to 127.0.0.1. Production API routing must be configured in the restricted admin Nginx vhost before a reviewed release; this task changes no Nginx ingress, credentials or running production service.

Account suspension, independent moderation reports/decisions/appeals, arbitrary message replay and blob deletion remain unimplemented. Storage is attached-media metadata, not an Azure account inventory or measured byte-usage report. The reviewed actions above are local work; no production deployment is authorized or claimed.

## Real-data local preview

A protected, read-only export of the production `hackways_prod` database is restored into a separate local `hackways_admin_preview` database. The source was PostgreSQL 16.15; the local restored instance uses installed PostgreSQL 18 on loopback port 55440. Export used `default_transaction_read_only=on` and a bounded lock wait. The archive SHA256 was checked before a successful transactional restore. Production schema, credentials, running containers and application records were not changed.

Active sessions, OAuth states/exchange tokens, email verification tokens, idempotency responses and authentication rate-limit rows were excluded from the copy. The snapshot and its checksum manifest live under the private Windows account directory `Documents/HackwaysLocalPreview`, outside Git, with access restricted to the current Windows account. Runtime connection information and the temporary Postman session environment are protected files there; no production Azure keys are installed in the local services.

The existing verified account approved by the user has a local-only admin grant. Its existing account password/hash was preserved. Sign in at `http://localhost:3003/login` using that account's existing password. The account's production privileges and credentials were not modified. A small copy timestamp in the UI distinguishes this snapshot from live production data.

`ADMIN_PREVIEW_ONLY=true` is accepted only for development, a loopback HTTP listener and a loopback database named exactly `hackways_admin_preview`. In this mode the same two Go services mount admin inspection/authentication, the reviewed admin detail/action routes and health/service metadata. Approved admin changes persist only in the restored local database; normal event/auth/storage mutation routes remain absent. Registration maintenance, email dispatch and housekeeping workers do not start. Queuing a retry or notification therefore does not send email from the copy. The normal production mode retains its existing routes and workers.

To restart the already prepared local preview:

```powershell
./deploy/scripts/start-admin-preview.ps1
```

The launcher loads the protected local source, starts only the restored local PostgreSQL and reviewed local Go binaries if needed, and starts the loopback-bound admin development server. It does not fetch production data, apply migrations, replace running processes or contact Azure. The `cmd/admin-preview` Go utility is separately limited to this local database and can provision the approved verified account's local grant and a protected short-lived Postman session for verification; it cannot provision production grants.

Postman CLI 1.75.0 verified all nine admin collections with cloud event reporting disabled. The actual local snapshot returned 3 events, 4 accounts, 6 email records, 4 attached media records and 5 audit entries; spaces, registrations and tickets were empty. Moderation returned the 3 draft/unpublished event records. Anonymous requests returned 401, and an ordinary event mutation route returned 404 in preview mode. Private diagnostic responses contain response bodies/status/tests only; credential-bearing request headers, cookies and script logs are removed. Session values stay only in the protected credential environment. No records or credentials were published to a Postman team/workspace.
